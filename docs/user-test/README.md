# User test kit (M10)

A moderated test of the alpha path with 5 to 8 people, run one at a time. It measures the two
success metrics in `docs/technical-spec.md` section 5 that need people rather than CI:

| Metric                       | Target               | Measured by                                             |
| ---------------------------- | -------------------- | ------------------------------------------------------- |
| Understanding gain           | +2 points on average | The same 5-question quiz before and after the session   |
| Setup finished in 2 sittings | 80% of participants  | Whether the alpha path was finished in this one sitting |

Everything in a session is synthetic: a sandbox bank, a made-up pay stub and a test account that
is deleted at the end. No participant enters anything about themselves.

## Files

| File                                           | Used when                                   |
| ---------------------------------------------- | ------------------------------------------- |
| [consent.md](consent.md)                       | Read aloud and signed before anything else  |
| [facilitator-script.md](facilitator-script.md) | The session, word for word where it matters |
| [quiz.md](quiz.md)                             | Before and after the tasks; key and scoring |
| [observation-sheet.md](observation-sheet.md)   | Filled in by the note taker, one per person |

## Who to recruit

- People in their first year at a first salaried job, or who will start one within six months
  (students with a signed offer count).
- Not on the project team, and not anyone who has seen the app before.
- Mix of comfort with money topics: aim for at least two people who say they "do not really know"
  what a 401(k) match is.

## Before the first session

1. Run the app against a non-production API with the Plaid sandbox and the fake or live model:
   either the deployed preview, or locally with `make dev` (see `README.md`). The Why screen must
   show a verified explanation, so check one end to end first.
2. Create one test account per participant (Supabase dashboard, "Auto Confirm User"), named
   `usertest-01@example.com`, `usertest-02@example.com` and so on, each with a password from a
   password manager. Never reuse an account between participants.
3. Put the synthetic pay stub `e2e/fixtures/acme-paystub.pdf` on the test laptop's desktop as
   `Acme pay stub.pdf`. It is generated by `node e2e/fixtures/make-acme-paystub.mjs` (run from
   `web/`); its SSN is an example number and its account number is masked.
4. Print or open the Plaid sandbox credentials card: username `user_good`, password `pass_good`,
   and, if Plaid asks for a code, `1234`.
5. Print one copy of the quiz per participant per round (before and after), and one observation
   sheet per participant.
6. Do a dry run with a teammate, timing each task.

## After each session

1. Sign in as that participant's test account and delete it from the account menu (Delete account,
   type `delete`). This removes the sandbox bank at Plaid and every row in the database. Note the
   time on the observation sheet.
2. Score both quizzes with the key in `quiz.md` and fill in the scoring sheet.
3. File any bug as an issue with the participant number, never a name.

## After all sessions

Summarize in `docs/user-test/results.md`: the scoring sheet, the share who finished in one sitting,
the top five problems by how many people hit them and how badly, and what changed because of them.
Keep consent forms on paper or in a private folder; they are not committed.
